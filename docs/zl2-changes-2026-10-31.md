## 2. Renderer / GL stack

### 2.1 SFPEW ab "compatibility layer" ban gaya (31 Oct — sabse naya bada change)
Commits: `dccc63e9`, `31760e14`, `2496e563`, `eeba94e0` (+ naya `SimpleFPEWrapper-release.aar` 8 456 192 → 8 558 630 bytes).

**Kya:**
- `SimpleFPEWrapperRenderer` (ek alag "renderer") hata diya. Ab `SimpleFPEWrapper.kt` ek **layer** hai jo kisi bhi renderer ke upar lag sakta hai — built-in (NG-GL4ES, VirGL, MobileGlues…) aur **plugin renderers** par bhi (`sfpewPluginLayer` setting).
- `SFPEW_EGL` ab `SDL_EGL_LIBRARY` / `POJAVEXEC_EGL` se aata hai, aur `SDL_EGL_LIBRARY` bhi SFPEW library par point karta hai → **auto EGL context mode** (naye AAR me `eglCreateContext`/`eglDestroyContext` intercept).
- JNI: `egl_loader.c` me `sfpew_eglCreateContext_p` / `sfpew_eglDestroyContext_p` (chaaron milne par hi enable — warna NULL, safe fallback), `gl_bridge.c` me `bridge_eglCreateContext()`.
- FPE emulator mods (`angelica`, `actinium`) detect hone par layer khud off.
- Per-version SFPEW settings (`VersionConfig`) + `RendererInterface.supportsSfpewByDefault()`.

**Kyu:** SFPEW pehle sirf "ya to ye renderer, ya wo" tha. Practically SFPEW ek *fix-up layer* hai (EGL/GL 4.x shim), isliye usko har renderer par optional lagana chahiye — isse woh devices bhi chal jate hain jahan standalone SFPEW entry confuse karti thi, aur Angelica/Actinium wale packs double-emulation se bach jate hain.

**Hamare yahan:** **NAHI**. Hum abhi bhi purana model chalate hain — alag `SimpleFPEWrapperRenderer` + purana AAR.
**Asar:** MobileGlues/plugin renderer ke saath SFPEW ka fayda milna, EGL context wale crashes ka fix.
**Risk:** JNI (`ctxbridges/egl_loader.c`, `gl_bridge.c`, `egl_bridge.c`) chhuna padega — aur humne `virgl_bridge.c` already ZL2-style modify kiya hua hai. Isliye ise alag branch/commit me, test ke saath karna chahiye. **Effort: M-L.**

### 2.2 MobileGlues version cap — upstream ne alag raasta chuna
ZL2 me ab `MobileGluesRenderer`:
```kotlin
override fun getMaxMCVersion(): String = "26.3-snapshot-3"
override fun getDisplayMaxMCVersion(): String = "26.2"
```
Yaani wo bundled **2.0.0** ke saath MC 26.4 ko support hi nahi karte (version list me limit lag jati hai) — wahi bug jiske kaaran hamare yahan black screen aayi thi.
Humne ulta kiya: **MG 2.0.1 (`MG_MOBILEGLUES_VERSION 2010`) bundle karke** 26.4 chalaya. Ye upstream se **aage** hai, isliye wo cap hamare liye nahi chahiye.
Dhyan: `enableNoError` default upstream me abhi bhi `0` (Auto/off) hai — humne bhi nahi chheda, kyunki fix ab library me hai.

- `31760e14` ke saath `Renderers.kt` se SFPEW entry hat gayi → renderer list chhoti aur saaf.
